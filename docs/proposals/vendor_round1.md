# پیشنهاد جدول‌های فروشندگان — دور ۱

**وضعیت: پیشنهاد؛ تأیید نشده. تا تأیید صریح مالک هیچ جدولی ساخته نمی‌شود** (قانون سند، بخش ۱ و ۷).
مبنا: مدل داده‌ی اپ وندوریاب (مخزن `RezaFarahanipy/Vendor`) که همین نوع اطلاعات را دارد؛ فیلدهای JSON/جداشده با ویرگول به جدول جدا تبدیل شده‌اند.

## فهرست جدول‌های پیشنهادی
| جدول | نام فنی | مسئولیت |
|---|---|---|
| فروشندگان | `vendors` | اطلاعات پایه (این دور) |
| آدرس‌ها | `vendor_addresses` | چند دفتر/کارخانه/انبار/نمایندگی |
| اطلاعات تماس فروشنده | `vendor_contacts` | تلفن، موبایل، ایمیل، وب‌سایت شرکت |
| اشخاص | `vendor_people` | افراد، سمت، تماس |
| حساب‌های بانکی | `vendor_bank_accounts` | بانک، شماره حساب، شبا، شعبه (حساس) |
| دسته‌بندی کالایی | `product_categories` + `vendor_categories` | درختی؛ چندبه‌چند |
| محصولات و برندها | `vendor_products`, `vendor_brands` | محصول، برند، نمایندگی |
| مدارک و مجوزها | `vendor_certificates` | نوع، تاریخ صدور/انقضا، فایل |
فایل‌ها: موتور اسناد (فاز ۴). ارزیابی: فاز ۷ (یکپارچه با سوابق ارزیابی).

بیرون از جدول: امتیاز (از ارزیابی‌ها محاسبه می‌شود)، علاقه‌مندی (ترجیح هر کاربر)، لوگو/کاتالوگ/کارت ویزیت (موتور اسناد)، آدرس و مختصات (جدول آدرس)، مدیرعامل (جدول اشخاص).

## پیش‌فرض‌های پیشنهادی (منتظر تأیید)
1. فقط نام رسمی اجباری است؛ بقیه‌ی شناسه‌ها اختیاری.
2. تکراری: هم‌شناسه‌ی ملی ← مسدود؛ نام مشابه (بدون تفاوت ي/ی، ك/ک، فاصله و نیم‌فاصله) ← فقط هشدار.
3. وضعیت‌ها: فعال، در انتظار تأیید، غیرفعال، مسدود. فروشنده‌ای که هوش مصنوعی از پیش‌فاکتور ثبت کند «در انتظار تأیید» می‌ماند.
4. نوع فعالیت: جدول مقادیر قابل ویرایش توسط مدیر (تولیدکننده، بازرگانی، واردکننده، پخش‌کننده، پیمانکار/خدماتی).
5. مدیرعامل فیلد جدا ندارد؛ در جدول اشخاص با سمت «مدیرعامل» ثبت می‌شود.
