# پیشنهاد دور ۴ — دسته‌بندی، کالا، برند و مدارک

**وضعیت: پیشنهاد؛ تأیید نشده.** مبنا: مدل وندوریاب (دسته‌بندی درختی، محصول با برند/مدل/کد فنی) و ماژول‌های بعدی (مقایسه‌ی قیمت فاز ۶).

## ایده‌ی کلیدی: کالای مرجع
نام یک کالا در هر پیش‌فاکتور فرق می‌کند («نبشی 3»، «نبشی ۳»…). برای مقایسه‌ی قیمت فروشندگان باید یک **کالای مرجع** باشد و نام هر فروشنده به آن وصل شود (مثل «طهران ← تهران»).

## جدول‌ها
**`items` — کالای مرجع**
| فیلد | نام فنی | نوع | الزام |
|---|---|---|---|
| کد کالا | `item_code` | متن، یکتا | خودکار |
| نام استاندارد | `name` | متن | اجباری |
| دسته | `category_id` | ارجاع به `lookup_values` (`product_category`، درختی) | اختیاری |
| واحد پیش‌فرض | `default_unit_id` | ارجاع به `lookup_values` (`unit`) | اختیاری |
| مشخصات | `specification` | متن | اختیاری |
| فعال | `is_active` | بله/خیر | اجباری |

**`item_aliases` — نام‌های مستعار کالا:** `item_id`, `alias`, `alias_key` (fold‌شده، یکتا).

**`vendor_products` — کالای ارائه‌شده‌ی فروشنده**
| فیلد | نام فنی | الزام |
|---|---|---|
| فروشنده | `vendor_id` | اجباری |
| کالای مرجع (خالی = هنوز وصل نشده) | `item_id` | اختیاری |
| نام نزد فروشنده | `vendor_item_name` | اجباری |
| برند | `brand_id` (`lookup_values` / `brand`) | اختیاری |
| مدل، کد فنی | `model`, `technical_code` | اختیاری |
| مشخصات | `specification` | اختیاری |
| واحد | `unit_id` | اختیاری |
| توضیحات، فعال | `notes`, `is_active` | |
قیمت اینجا ذخیره **نمی‌شود** (از پیش‌فاکتورها و لیست قیمت می‌آید) تا کهنه نشود.

**`vendor_categories`:** `vendor_id`, `category_id` (چندبه‌چند؛ فروشنده در چند دسته).

**`vendor_brands` — برند و نمایندگی:** `vendor_id`, `brand_id`, `relation_type_id` (نماینده‌ی رسمی، توزیع‌کننده، تولیدکننده، فروشنده‌ی آزاد)، `since_date`, `notes`, `is_active`.

**`vendor_certificates` — مدارک و مجوزها**
| فیلد | نام فنی | الزام |
|---|---|---|
| فروشنده | `vendor_id` | اجباری |
| نوع مدرک (پروانه، ISO، نمایندگی…) | `certificate_type_id` | اجباری |
| شماره، صادرکننده | `number`, `issuer` | اختیاری |
| تاریخ صدور / انقضا | `issue_date`, `expiry_date` | اختیاری |
| فایل | `file_id` (موتور اسناد، فاز ۴) | اختیاری |
| توضیحات، فعال | `notes`, `is_active` | |
وضعیت (معتبر / نزدیک انقضا / منقضی) از تاریخ انقضا **محاسبه** می‌شود و ذخیره نمی‌شود.

## روابط
فروشنده ← چند کالا، چند دسته، چند برند، چند مدرک. کالای مرجع ← چند نام مستعار و چند `vendor_products`.

## پیش‌فرض‌های پیشنهادی (۱۷ تا ۲۱)
17. کالای مرجع (`items`) + نام‌های مستعار داشته باشیم؛ هوش مصنوعی در پیش‌فاکتور کالا را به کالای مرجع وصل پیشنهاد می‌دهد («نبشی 3 ← نبشی ۳؟») و فقط با تأیید ثبت می‌شود.
18. دسته‌بندی کالا یک لیست درختی در `lookup_values` (`product_category`) باشد، نه جدول جدا.
19. برند یک لیست استاندارد (`brand`) و رابطه‌ی فروشنده با برند در `vendor_brands`.
20. مشخصات فنی فعلاً متن آزاد؛ صفت‌های ساختاریافته (ضخامت، ابعاد، استاندارد) بعد از دیدن نمونه‌ی واقعی چند کالای فولادی.
21. وضعیت مدارک از تاریخ انقضا محاسبه شود؛ یادآوری ۳۰ روز قبل از انقضا (قابل تنظیم).
